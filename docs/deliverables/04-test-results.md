# 04. 테스트 결과표 — 흙과불 도자기공방 (고객사 11)

- 날짜: 2026-11-13 / 환경: 로컬(백엔드 :3001, 프론트 :3000), 시험 자료는 가상 seed 데이터
- 방법: API는 curl로 직접 요청, 화면은 브라우저로 375px·1280px 확인
- 요약: **총 69건 — 통과 58 / 실패 6 / 미구현 2 / 확인 불가 3**
- 미구현 2건: 자료 질문(`/ask`), 자료 관리 업로드·검색(`/staff/documents`) — 테스트 시점 기준

## 발견한 문제

### P-01 택배 작품이 발송 없이 '수령'으로 넘어감 (중)
- 재현: 작품 수령 방식 DELIVERY(PREPARING) → DONE 까지 단계 이동 → `PATCH /staff/works/:id/stage {"direction":"next"}` → 200, stage PICKED_UP, shipStatus PREPARING 그대로. `bulk-next` 도 같은 길(moveOne 공용).
- 영향: 수강생 화면엔 '수령'인데 송장 없음. 이 상태에선 `ship` 도 "완성된 작품만…" 400 이라 송장을 넣을 길이 없음(되돌리기 필요).
- 원인: `works.service.ts moveOne` 에서 `to === 'PICKED_UP' && pickupMethod === 'DELIVERY' && shipStatus !== 'DELIVERED'` 막는 조건 없음.

### P-02 배송중 작품을 완성 이전으로 되돌릴 수 있음 (낮음)
- 재현: DONE+SHIPPING 작품 → stage prev → 200, GLAZE_FIRED + shipStatus SHIPPING, completedAt null.
- 원인: moveOne prev 에 배송 상태 검사 없음.

### P-03 수강생 조회 반복 대입 제한 없음 (중, 보안)
- 재현: `POST /me/lookup` 같은 예약번호로 뒤4자리만 바꿔 15번 → 모두 404, 막힘 없음.
- 영향: 예약번호가 `REG-033`, `DM-0919-1` 처럼 짐작 가능 + 뒤4자리 1만 가지 → 이름·작품·환불 요청(`/me/cancel-request`)까지 남이 할 수 있음. `/me/makeups`, `/me/cancel-request` 도 같은 방식.
- 제안: IP·예약번호별 시도 횟수 제한(Nest throttler 또는 메모리 카운터).

### P-04 직원 대리 등록이 지난 수업에도 됨 (낮음)
- 재현: `POST /staff/classes/404/reservations`(11-11, 지난 수업) → 201.
- 공개 신청은 400. 사후 기록 용도라면 의도일 수 있음 → 기획 확인 필요.

### P-05 수강생 인증 방식이 명세와 다름 (낮음, 문서)
- 03-spec.md 5장·7장: `POST /me/verify` → 1시간 토큰 → `GET /me`. 구현·api.md: `POST /me/lookup` 매번 확인. 명세 문서를 구현에 맞춰 고쳐야 함.

### P-06 단체 문의 희망 날짜에 지난 날짜 허용 (낮음)
- 재현: preferredDate "2020-01-01" → 201. 직원 화면에 "희망 1. 1." 로 연도 없이 보여 올해 날짜로 오해 가능.

### 참고(문제는 아님)
- `GET /staff/reservations/search?q=1BA78A` 결과에 관계없는 예약(전화번호에 숫자 일부가 겹치는 것)이 섞여 나옴. 검색 정확도 개선 여지.
- 이미 배송완료된 작품에 ship 하면 "이미 배송이 끝난 작품이에요" 대신 "완성된 작품만 발송할 수 있어요"(검사 순서). 결과(400)는 맞음.
- 작품 목록 맨 위 W261114-01(박아름, 수업일 11-14 = 내일) 이 성형 단계로 있음. 다른 작업자가 만든 데이터로 보임, 미래 수업에 작품 등록이 막히지 않음.
- 404 화면이 Next 기본 영어 문구.
